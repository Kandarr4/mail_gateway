Автономный почтовый шлюз для Windows. Принимает входящую почту по SMTP,
складывает её в собственную базу и отдаёт вашему приложению через HTTP API.
Отправка — `POST`-запросом, получение новых писем — опросом с курсором. Внешние
почтовые провайдеры не участвуют, а сам шлюз ничего не знает о системе, которая
его использует.

Поставляется службой Windows со значком в трее и веб-панелью, ставится одним
установщиком Inno Setup.

```
                    ┌──────────────────────┐
  интернет ─SMTP───▶│  слушатель aiosmtpd  │──▶ SPF / DKIM / DMARC
                    │        :25           │        вердикт
                    └──────────┬───────────┘
                               ▼
                    ┌──────────────────────┐
                    │ SQLite + SQLAlchemy  │  тела и вложения
                    │  тела шифруются      │  зашифрованы на диске
                    └──────────┬───────────┘
                               ▼
 ваше приложение ◀─HTTP─│ FastAPI :8025 │──▶ воркер очереди ─DKIM─▶ интернет
      опрос по курсору      панель /admin      повтор с откатом
```

## Что здесь интересного

- **Шифрование на диске с осознанным исключением.** Тела писем и вложения
  шифруются Fernet, а адреса и темы сознательно остаются открытыми — по ним
  ищут панель и API. Компромисс описан, а не спрятан.
- **Проверка входящей почты как политика, а не переключатель.** SPF, DKIM и
  DMARC проверяются на каждом письме, и результат включает одну из трёх
  политик: `annotate` (записать вердикт), `enforce` (отклонять при провале) или
  `off`. Вердикт хранится рядом с письмом, поэтому спор о доставке можно
  разобрать потом.
- **Подпись DKIM по каждому домену.** У каждого домена свой селектор и свой
  приватный ключ — один шлюз корректно подписывает почту нескольких доменов.
- **Мультитенантность с хешированными ключами.** API-ключи хранятся как
  SHA-256, никогда в открытом виде; каждое письмо принадлежит конкретному
  клиенту, и арендаторы не видят чужую почту.
- **Доставка, переживающая сеть.** Воркер очереди повторяет отправку с
  экспоненциальным откатом и джиттером, ограничивает показатель вместо счёта
  `2**49`, разбирает отчёты о недоставке и сдаётся только после заданного числа
  попыток.
- **Лицензия не держит службу в заложниках.** Подписанный RSA-PSS файл лицензии
  ограничивает только *почтовый путь*: без действующей лицензии служба всё
  равно запускается, панель открывается, очередь просто встаёт на паузу, а SMTP
  отвечает `451`. Потеря лицензии не должна означать потерю настроек заказчика.
- **Миграции схемы под межпроцессной блокировкой.** Служба и программа в трее
  стартуют одновременно и обе накатывают Alembic; без файловой блокировки второй
  процесс падал на `duplicate column name`. Блокировка — это исправление, и
  причина записана рядом с ней.
- **Шаблоны шифруются в поставке.** `build.py` превращает шаблоны Jinja в `.enc`
  и подключает собственный загрузчик, чтобы в поставляемом каталоге не лежал
  читаемый HTML.
- **Строгий линт для продукта про безопасность.** `ruff` работает с
  включёнными `bandit` (`S`), blind-except (`BLE`), правилами имён (`N`) и
  асинхронности (`ASYNC`). Каждое подавление называет правило и причину.

## Запуск

```bat
copy .env.example .env
:: отредактируйте .env — минимум MG_DOMAIN и MG_API_TOKENS
run.bat
```

Или вручную:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Схема БД накатывается автоматически при старте. Интерактивная документация
API: `http://<host>:8025/docs`, веб-панель: `http://<host>:8025/admin`.

## Раскладка

| Путь | Что внутри |
|------|-----------|
| `app/api/` | HTTP API: маршруты, зависимости, обработка ошибок |
| `app/web/` | Веб-панель `/admin`, шаблоны и их шифрованный загрузчик |
| `app/services/` | Предметная логика: приём, доставка, DKIM, лицензии, ключи, ящики |
| `app/workers/` | Фоновые задачи: отправка очереди, обслуживание, резервные копии |
| `app/models.py`, `app/schemas.py` | Таблицы SQLAlchemy и контракты Pydantic |
| `app/config.py` | Все настройки из `.env`, единственный источник значений |
| `tray/` | Значок в трее, диалоги настроек, первичной настройки и лицензии (PySide6) |
| `installer/` | Сборка дистрибутива: Inno Setup и генератор соглашения |
| `migrations/` | Миграции Alembic |
| `tests/` | 346 тестов (`pytest`) |
| `docs/` | Полное руководство, ТЗ и инструкция по развёртыванию |

Точки входа: `run.py` (консоль), `service.py` (служба Windows),
`mailgateway.py` (единая программа со значком в трее), `manage.py`
(обслуживание из командной строки), `build.py` (сборка поставки).

## Конфигурация

Все настройки — переменные окружения с префиксом `MG_`, читаются из `.env` в
корне. Образец со всеми ключами и пояснениями — `.env.example`; при первом
запуске недостающие ключи и секреты создаются автоматически.

В репозиторий не попадают и остаются только на машине:

- `.env` — рабочие настройки с токенами API;
- `data/keys/encryption.key` — ключ шифрования тел писем и вложений;
- `data/dkim/*.private` — приватные ключи DKIM;
- `data/` целиком — вложения, журналы, резервные копии;
- `*.lic` — выданные лицензии;
- `mail_gateway.db` — база с почтой;
- `docs/generate/config_local.py` — реальные реквизиты и цены (в репозитории
  лежит обезличенный образец `config.py`).

## Проверка

```bat
test.bat
```

Прогоняет модульные тесты (`pytest`) и сквозной `smoke_test.py`, который
поднимает шлюз на временной базе, шлёт письмо по SMTP и дёргает API.

```bat
.venv\Scripts\python.exe -m ruff check .
```

## Сборка поставки

```bat
.venv\Scripts\python.exe build.py
```

Собирает onedir-каталог PyInstaller, шифрует HTML-шаблоны в `.enc` и готовит
установщик Inno Setup. Соглашение и версия для установщика создаются командой
`installer/make_license.py`, документы `.docx` — командой `make_docs.bat`;
сгенерированные файлы в репозитории не хранятся.
